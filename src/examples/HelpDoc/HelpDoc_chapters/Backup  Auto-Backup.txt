[>c] # Backup / Auto-Backup

By default, every time you close WareWoolf, it will automatically backup the current project by creating a zipped file containing it in the designated Backups directory, which you can change in the “Settings” page. (So, for instance, if you’re using WareWoolf on a writerDeck, you may designate the backup folder to be on a USB thumb drive in case your main filesystem becomes corrupted.) 
	Each backup file is saved with the project filename as a base and then a 14-digit timestamp (4 year digits, 2 month, 2 day, 2 hour, 2 minutes, 2 seconds) so that when sorted alphabetically they are also sorted chronologically. You can set how many of the most recent backups WareWoolf keeps, or set this limit to 0 to keep all of them indefinitely. On top of those recent ones, it also keeps the newest backup of each day for the last 30 days, and the newest backup of each week before that—so a day spent opening and closing the project many times will not push out last week’s backups. Every time it saves a backup, it deletes any that none of these rules keep.
	Should you ever need to revert to a backup, use **File > Restore Backup**. It lists the current project’s backups by date, newest first (tick the box to see every project’s backups instead). Choose one and press Restore (or Enter), and WareWoolf unzips it into its own folder beside the archive in your Backups folder and opens it. The project you had open is not changed—if it has unsaved changes you are offered a save first—and you can use Save As to keep the restored copy wherever you want it. (You can still unzip a backup by hand with the File Manager’s Unzip button if you prefer.)
	In addition to Auto-Backup, you can manually create a backup file at any time using the File > Backup tool. It will follow the same rules of deletion as are set up for Auto-Backup.

## Save Copy
**File > Save Copy** is the third way to put your work somewhere else, and it is worth knowing how it differs from the other two. It writes a complete copy of the project—the .woolf file and every chapter—wherever you choose, and then leaves you working in the original, exactly where you were. **Save As**, by contrast, moves you: the new copy becomes the project you are editing, and the old files stay behind untouched.
	So Save Copy is what you want for striking off a version before a big revision—“Novel before cutting chapter nine”—without interrupting yourself. Unlike a backup, the copy is an ordinary project you can open straight away rather than a zipped archive, and it is not counted among the backups WareWoolf keeps, so it will never be deleted to make room for a newer one.
