[>c] # Using WareWoolf For A WriterDeck

WareWoolf is designed to work on a desktop computer, but its primary purpose is for use on a writerDeck. This is why it is optimized for use without a mouse and has built-in email functions.
	The wiki page of the same name (github.com/brsloan/warewoolf/wiki) has the same steps as this chapter with copy-and-paste command blocks.

## What is a writerDeck?
A writerDeck is a device dedicated specifically and solely to writing. Technically, a typewriter is an analog writerDeck. But usually we mean some sort of computerized word processor, such as the Astrohaus Freewrite or the Alphasmart Neo, to name two of the most popular mass-produced versions. But these tend to be either too expensive or too limited for many writers, so many of us build our own.
	For more on writerDecks, see www.writerdeck.org.

## What you need
A 64-bit Raspberry Pi (3, 4, 5, Zero 2 W or later); WareWoolf’s current releases are 64-bit only. A microSD card, a screen, and a keyboard. Raspberry Pi OS *Lite* (64-bit), Bookworm or newer; “Lite” means no desktop, which is the point. A network connection during setup. And, optionally but very handily, a second computer to SSH in from, so you can paste commands instead of typing them at the Pi.
	The same recipe works on any Debian-family machine with no desktop, such as an old laptop with Debian installed and the desktop left out.

## The quick way: the setup script
The WareWoolf source code includes a script, scripts/setup-writerdeck.sh, that does every step in the next section for you.
	1. Write Raspberry Pi OS Lite (64-bit) to the card with the Raspberry Pi Imager. In the Imager’s settings, set a username and password, your Wi-Fi network, and enable SSH. Boot the Pi.
	2. Log in, at the Pi’s keyboard, or from another computer log in remotely with “ssh yourname@raspberrypi.local”.
	3. Download the script:
		curl -fsSLO https://raw.githubusercontent.com/brsloan/warewoolf/main/scripts/setup-writerdeck.sh
	4. Run it, as your ordinary user, not with sudo (it asks for your password where it needs it):
		bash setup-writerdeck.sh --poweroff-on-exit
	5. Reboot:
		sudo reboot
	The Pi comes back up, logs you in, and opens WareWoolf. That’s it!
	Options you can add after the script’s name: **--poweroff-on-exit** shuts the machine down when you close WareWoolf instead of dropping to a console. **--keep-cursor** leaves the mouse pointer visible (it is hidden by default). **--network-manager** installs NetworkManager so the Wi-Fi Manager works on Bullseye (Bookworm and newer already have it). **--deb PATH** installs a .deb you already have instead of downloading the latest release. **--no-autologin** leaves you typing your password at each boot. **--reboot** reboots as soon as it finishes.
	The script installs the xorg, matchbox-window-manager and x11-xserver-utils packages and the WareWoolf .deb, sets console autologin for your user, writes ~/.xinitrc (backing up any existing one beside it), and adds a marked block to ~/.bash_profile, leaving anything else in that file alone. Running it again is safe. To undo it, delete the marked block from ~/.bash_profile, delete ~/.xinitrc, and set raspi-config > System Options > Boot back to “Console”.

## The long way: every command, by hand
This is exactly what the script does, in the same order. Do these at the Pi’s keyboard or over SSH, logged in as your ordinary user.

### 1. Install the OS
Write Raspberry Pi OS Lite (64-bit) to the card with the Raspberry Pi Imager, setting your username, password, Wi-Fi and SSH in the Imager’s settings. Boot the Pi and log in. (If you skipped the Imager settings, “sudo raspi-config” can set Wi-Fi under System Options and SSH under Interface Options.)

### 2. Update the package lists
		sudo apt-get update

### 3. Install Xorg, Matchbox, and xset
		sudo apt-get install -y xorg matchbox-window-manager x11-xserver-utils
	This is the slow step: a Lite image has almost none of the dependencies, so expect several minutes. Afterwards, “which startx matchbox-window-manager xset” should print three paths.

### 4. Install WareWoolf
WareWoolf is not in the Debian or Raspberry Pi repositories, so you install its .deb file directly. Get the current one from github.com/brsloan/warewoolf/releases: the file ending in \_arm64.deb for a 64-bit Pi. Download it on the Pi with curl, or download it on another computer and copy it over with scp. Then install it with apt-get rather than dpkg, so the dependencies come with it (the path must start with / or ./):
		sudo apt-get install -y /tmp/warewoolf\_3.1.0\_arm64.deb
	Afterwards, “which warewoolf” should print /usr/bin/warewoolf.

### 5. Log in automatically at boot
Without this, every boot stops at a login prompt. Older versions of this chapter left it out, and it is the most common reason “it boots to a login prompt instead of the app.”
		sudo raspi-config nonint do_boot_behaviour B2
	B2 is “Console Autologin”, the same as sudo raspi-config > System Options > Boot / Auto Login > Console Autologin. On plain Debian with no raspi-config, the wiki page has the systemd override that does the same thing.

### 6. Tell X what to run: ~/.xinitrc
When you run startx, X reads ~/.xinitrc and runs it. When the last command in it finishes, X exits. So the file starts the window manager in the background, runs WareWoolf in the foreground, and cleans up when WareWoolf closes. Create it (nano ~/.xinitrc) with these lines:
		xset s off
		xset s noblank
		xset -dpms
		matchbox-window-manager &
		wm_pid=$!
		warewoolf
		kill "$wm_pid"
	The three xset lines stop the screen from blanking while you sit and think. The kill line takes the window manager down when WareWoolf closes, so X exits instead of leaving an empty black screen. (Older versions of this chapter had “kill pid” without the dollar sign, which did nothing.)
	If you would rather the machine turned itself off when you close WareWoolf, add one more line at the end: “systemctl poweroff”. It works without a password because you are logged in at the machine’s own console. But think twice: if WareWoolf ever fails to start, the machine will power itself off a moment after every boot, and you will have to SSH in quickly or edit the card on another computer to fix it. Leaving it out means closing WareWoolf drops you to a shell prompt instead, which is the safer place to be while you are still tinkering.
	Now test it, at the Pi’s keyboard (not over SSH): type “startx”. WareWoolf should open full screen, alone, with no desktop. Close it (Ctrl+Shift+X) and you should be back at the prompt.

### 7. Start X at login: ~/.bash_profile
~/.bash_profile runs every time you log in. Add these lines to it (nano ~/.bash_profile). They run startx only when you are logging in at the first console of the machine itself, so an SSH login still gives you a normal shell:
		if [ -z "$DISPLAY" ] && [ "$(tty)" = /dev/tty1 ]; then
		    startx -- -nocursor
		    echo "WareWoolf has closed. Type startx to open it again, or sudo poweroff to shut down."
		fi
	“-- -nocursor” hides the mouse pointer; if you use a mouse, write startx on its own. Notice that startx is *not* run with “exec”, as older versions of this chapter had it. With autologin on, “exec startx” means that closing WareWoolf ends your login, the console logs you straight back in, and WareWoolf reopens: an app you can never get out of.

### 8. Reboot
		sudo reboot
	The Pi should boot, log you in, and open WareWoolf.

### 9. NetworkManager, for the Wi-Fi Manager
WareWoolf’s Wi-Fi Manager talks to NetworkManager through nmcli. Raspberry Pi OS Bookworm (October 2023) and newer use NetworkManager already, so there is nothing to do; “systemctl is-active NetworkManager” prints “active”. On Bullseye, which uses dhcpcd instead, install NetworkManager and switch to it:
		sudo apt-get install -y network-manager
		sudo apt-get install -y --only-upgrade raspi-config
		sudo raspi-config nonint do_netconf 2
	That last line is Advanced Options > Network Config > NetworkManager in the raspi-config menus. Switching network stacks may drop an SSH session and forget the Wi-Fi password, so do this last, at the Pi’s keyboard if you can, and reconnect afterwards through WareWoolf’s own Wi-Fi Manager.

## Living with it
**Getting to a terminal.** Everything on the Pi is still there behind WareWoolf. Close WareWoolf (Ctrl+Shift+X) and you land at a shell prompt; “startx” reopens it. Or SSH in from another computer.
	**Updating WareWoolf.** The Check For Updates button in Help > About tells you when a new version is out. On Linux it cannot install it for you, so close WareWoolf, download the new .deb at the console or over SSH, and install it as in step 4. Or run the setup script again: it reinstalls the latest release and leaves everything else as it was.
	**Email passwords.** A Lite image has no keyring service, so WareWoolf has nowhere secure to hand your Gmail app password to. When you save it, tick “Protect With Passphrase?” in the Send dialog; WareWoolf will ask for the passphrase once per session.
	**Screen blanking.** The xset lines in ~/.xinitrc stop X from blanking the screen after ten minutes. If you would like it to blank, to save a battery, delete those three lines.

## Rebooting From Inside WareWoolf
On Linux, the File menu ends with a **Reboot** item (it isn’t there on Windows or Mac, where you already have a desktop to do it from). On a writerDeck that boots straight into WareWoolf, this is usually the only way to restart the machine without leaving your manuscript for a terminal.
	It behaves exactly like Exit, except that the machine comes back: if you have unsaved changes you are asked about them first, and if you have auto-backup switched on, the backup runs before anything shuts down. There is no keyboard shortcut for it, on purpose.
	If your system refuses the reboot — some setups only allow it for an administrator — WareWoolf will tell you what it said rather than appearing to do nothing. To shut down rather than reboot, either set up poweroff-on-exit as above, or close WareWoolf and type “sudo poweroff”.

## Troubleshooting
**It boots to a login prompt, not WareWoolf.** Autologin is not set. Do step 5.
	**It logs in but just sits at a shell prompt.** The ~/.bash_profile block is missing or not running. Check the file, and that “tty” prints /dev/tty1.
	**startx gives a black screen and returns.** Look for lines marked EE in ~/.local/share/xorg/Xorg.0.log. If X starts but WareWoolf does not, SSH in from another computer and run “DISPLAY=:0 warewoolf” to see what it prints.
	**WareWoolf closes and immediately reopens.** ~/.bash_profile has “exec startx” in it. Remove the “exec”.
	**The machine turns off right after booting.** ~/.xinitrc ends with systemctl poweroff and WareWoolf is failing to start. SSH in, or mount the card on another computer, and remove that line, then find out why WareWoolf is not starting.
	**The Wi-Fi Manager says nmcli is not installed, or shows nothing.** NetworkManager is not running. See step 9.
	**File > Reboot says “Interactive authentication required.”** systemd is not treating your login as a local session, which usually means X was started from somewhere other than the console autologin. Reboot from the console, or from WareWoolf once you have booted normally.
	**The keys on my keyboard are not what WareWoolf expects.** Open the Shortcut Helper (Ctrl+H) and rebind them.
	**Something else went wrong.** Welcome to tinkering with Linux. The issue tracker at github.com/brsloan/warewoolf/issues is a good place to ask.
